# Endaoment：让资金加班

每个协议都有金库，但大多数金库只是让数百万美元闲置。

Endaoment 让每一美元都发挥作用。[债券](../governance-and-economics/03-bonds.md)和 [Reserve Engine](../governance-and-economics/04-reserve-engine.md)的付款会成为协议自有资本，由治理部署到 DeFi 各处，用于赚取收益、增加 GREEN 流动性和[维护锚定](01-green-stablecoin.md)。这是一个为增长而建，而不只是为了持有资产的金库。

> **实时条款以链上为准。** 启用了哪些集成、资金池和 PSM 设置，会因部署而异并随时间变化。本页所有数字均为示例。[Params](https://params.ripe.finance) 才是权威来源。

## Endaoment 为何存在

大多数金库必须二选一：为了安全让储备闲置，或为了增长部署资本。Endaoment 两者兼顾：

1. **通过收益策略增加协议财富。**
2. **在参考资金池中并通过 PSM 维护 GREEN。**
3. **按治理指令行动**——每次部署都是一笔经提交的链上交易。
4. **保留所得收益**，为下一步提供资金。

## 三合约架构

```
┌─────────────────────────────────────────────────────────────┐
│                     ENDAOMENT 系统                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────────────┐   ┌───────────────┐   ┌───────────────┐  │
│  │     金库      │   │   Endaoment   │   │      PSM      │  │
│  │   （Vault）   │◄──│  （运营方）   │──►│ （锚定维护者）│  │
│  └───────────────┘   └───────────────┘   └───────────────┘  │
│                                                             │
│    持有协议资产       兑换、LP、收益、      GREEN ↔ 储备     │
│                       稳定锚定              稳定币，按 1 美元 │
│                                           + 储备收益         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Vault（金库）**——资金存放的地方。只有运营方可以提取。

**Operator（运营方）**——系统的大脑。负责兑换、流动性、收益策略和 GREEN 稳定器。

**Peg Defender（锚定维护者）**——按 1 美元在 GREEN 与储备稳定币之间兑换，并设置限制以防滥用。

## 价值从何而来

```
债券 / Reserve Engine 付款 → 金库 → 收益与流动性 → 协议实力
            ↑                                      ↓
            └──────────── 更多用户信心 ←───────────┘
```

为债券或 Reserve Engine 配额支付的每一枚稳定币都会成为金库资本（债券购买时即铸造 RIPE；Reserve Engine 只在归属时铸造）。金库还会收到稳定池在清算中支付的非 GREEN 资产，以及去杠杆从仓位取得的稳定币。所有资产都可以部署到 DeFi 赚取收益、为 GREEN 交易提供流动性，并在市场承压时支持协议。

## 核心能力

### 1. 智能稳定 GREEN

**平衡规则：** 按相同价值尺度比较参考资金池中的 GREEN 与配对稳定币。哪一侧更重，就移动差额的一部分——不会一次移动全部差额。

**GREEN 走弱时**（池中 GREEN 过多）：

* 提取 GREEN 流动性。
* 在池已记录债务范围内销毁 GREEN。
* 资金池重新平衡，价格逐步回到 1 美元附近。

**GREEN 走强时**（池中 GREEN 过少）：

* 增加 GREEN 流动性，优先使用金库已有 GREEN。
* 铸造其余部分，记作资金池债务，但不超过上限。
* 资金池变深，价格逐步回到 1 美元附近。

每次操作都由治理提交，不会按定时器自动运行。而且只有当金库净头寸不会变差时，操作才会通过——稳定器绝不会以削弱金库为代价维护锚定。

### 2. 锚定稳定模块（PSM）

没有滑点，也没有 DEX 的复杂过程：PSM 在 GREEN 与其储备稳定币（部署时固定为一种稳定币）之间按 1 美元直接兑换，具体方向取决于治理启用了哪一侧。

* **铸造 GREEN：** 存入储备稳定币，按 1:1 获得 GREEN（如果选择 sGREEN，只要铸造金额超过 1 GREEN，全部金额都会自动包装成 sGREEN）。
* **赎回 GREEN：** 销毁 GREEN 或 sGREEN，按 1:1 获得储备稳定币。

```
GREEN 低于 1 美元？
→ 套利者买入便宜的 GREEN
→ 通过 PSM 赎回价值 1 美元的储备稳定币
→ 买盘压力使锚定恢复

GREEN 高于 1 美元？
→ 套利者用价值 1 美元的储备稳定币铸造 GREEN
→ 在市场卖出赚取差价
→ 卖盘压力使锚定恢复
```

**保护措施**

* 每个时间区间分别限制铸造和赎回金额。
* 可选费用，以及用于受控上线的可选白名单。
* 报价采用储备稳定币的预言机价格与 1:1 中对您较不利的一项；受认可的 Underscore 金库不受限额、白名单和费用约束，并在赎回时获得更有利报价。
* 赎回金额不超过总储备。

**闲置储备？仍在工作。** 如果治理设置了收益金库，PSM 会将全部闲置储备余额转入其中，并在赎回需要资金时取回。

### 3. 通过 Underscore 获取收益与流动性

Endaoment 通过 [Underscore Protocol](https://underscore.finance/) 接入 DeFi。其标准化适配器注册表（“Legos”）让每项集成都使用相同指令：存入或提取收益仓位、兑换、添加或移除流动性、领取激励。新集成注册后即可使用。每次部署都是独立的治理提交交易，并带有治理设置的最低输出检查，同时承担目标场所本身的风险。

### 4. 战略合作伙伴计划

**对合作伙伴：** 与金库共同投资并分享 LP 仓位。

**对 Ripe：** 无需稀释即可加深 GREEN 市场，并增加新的收入来源。

运作方式：合作伙伴的资产进入金库；协议用等值 GREEN 与之配对（优先使用金库 GREEN，其余部分铸造）；LP 代币按 50/50 分配；资金池未接收的任何新铸 GREEN 都会被销毁。

## 协议收入去向

### 收入分配

发起费和借款人利息可以分成两部分：

* **sGREEN 收益：** 流向 [sGREEN](../earning-and-rewards/01-sgreen.md) 持有人。
* **治理分配：** 以 GREEN 转给治理，用于回购 RIPE。

分配比例由治理设置，默认 100% 发送给 sGREEN。协议本身只负责转移 GREEN；任何 RIPE 回购都是治理另行执行的操作。详见 [RIPE 价值累积](../governance-and-economics/01-ripe-tokenomics.md#ripe-jia-zhi-lei-ji)。

### 金库收益

除非治理另有安排，Endaoment 赚取的所有收益都留在金库中——可以流向 RIPE 质押者、sGREEN 持有人，或继续投入下一项策略。

## 复利效应

金库不只是最后防线，也是增长引擎。

每售出一份债券，就增加一份燃料。每次收获收益，都继续复利。每次稳定器操作都必须让金库至少与之前一样强，否则就不会执行。其他金库以持有多少美元衡量成功；Endaoment 以赚取多少美元衡量成功。
